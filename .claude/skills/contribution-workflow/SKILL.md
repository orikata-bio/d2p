---
name: contribution-workflow
description: Prepare a focused public intake or release PR with a change/test summary and contributor/source credits, preserving maintainer approval and required checks.
---

Read AGENTS.md, CONTRIBUTING.md and the repository PR template. Use a focused
branch, preserve other workers' changes and run affected and required checks.
Public PRs contain a normal summary, validation and appropriate source/author
credits. Full human/agent work disclosures stay in the linked private development
PR, which retains the original public PR and exact source commit.

A company maintainer must approve an outside contribution's exact head before
privileged internal testing. Use only an explicitly configured private dev pair.
Run product CI and authorized review vendors there. Return accepted changes
through the established curated export and a separate public release PR. Preserve
licenses, author credit, branch protections and release checks. Do not export
private history or internal work records. Public/release repos do not run the
full disclosure validator, CodeRabbit or Greptile. Unconfigured routing remains
inactive. Never invent permission for reviewers, subscriptions or automatic merges.
